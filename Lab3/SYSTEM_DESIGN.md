# System Design — ระบบประเมินและคาดการณ์ผลกระทบจากภัยแล้งต่อพืชเศรษฐกิจ

เอกสารนี้อธิบายสถาปัตยกรรมและการไหลของข้อมูลของระบบ GOTTALOMLOK แล้ง
เนื้อหาตรงกับหัวข้อ 3 ของรายงานฉบับเต็ม และปรับปรุงตามสถานะล่าสุดของระบบ

---

## 1. MVP ของระบบนี้

> **หนึ่งเลเยอร์ที่ใช้งานได้จริง** — ดัชนีเสี่ยงภัยแล้งต่อพืชเศรษฐกิจ 4 ชนิด รายอำเภอ
> ครอบคลุม 928 อำเภอทั่วประเทศ ที่ผู้ใช้เปิดบนมือถือแล้วคลิกดูค่าของอำเภอตนเองได้
> วาดขอบเขตเพื่อสรุปผล และส่งออกข้อมูลไปใช้ต่อได้

| องค์ประกอบ | การตีความในโครงการนี้ |
|---|---|
| **Minimum** | ตัดระบบสมาชิก ระบบแจ้งเตือนอัตโนมัติ และแดชบอร์ดผู้บริหารออกทั้งหมด เหลือแผนที่ความเสี่ยงหนึ่งชั้นที่ทำงานครบวงจร |
| **Viable** | คลิกแล้วมีค่าขึ้นจากฐานข้อมูลจริง ไม่ใช่ mockup · ส่งออกไฟล์ได้จริง 4 รูปแบบ · มี API ที่เรียกจากภายนอกได้ |
| **Product** | เปิดใช้ได้ทันทีจากเบราว์เซอร์บนมือถือ แท็บเล็ต และคอมพิวเตอร์ โดยไม่ต้องติดตั้งซอฟต์แวร์ |

**สิ่งที่ตัดออกอย่างจงใจ:** การแสดงผลระดับตำบลเป็นทางเลือกเสริม · โมเดลพยากรณ์เป็น baseline
ยังไม่ใช่ deep learning ที่ผ่านการตรวจสอบ · การอัปเดตเป็นแบบ batch ตามรอบดาวเทียม ไม่ใช่ streaming

## 3. Data Flow หนึ่งรอบการทำงาน

รอบการทำงานกำหนดไว้ที่ **8 วัน** ล้อตามรอบซ้ำของ Sentinel-1 (6 วัน) และ MODIS composite (8 วัน)

1. **รับข้อมูลเข้า** — ภาพดาวเทียมและข้อมูลฝนถูกประมวลผลบนเซิร์ฟเวอร์ของ Google Earth Engine
   ไม่มีการดาวน์โหลดภาพมาเก็บบนเครื่องแม่ข่ายของระบบ
2. **คำนวณดัชนี** — SPI-3 จากฝนสะสม 90 วัน (CHIRPS) · VHI จาก NDVI และอุณหภูมิพื้นผิว (MODIS)
   · ความชื้นดินผิวจากค่าการกระเจิงกลับ VV (Sentinel-1)
3. **Zonal statistics** — เฉลี่ยค่ารายพิกเซลลงสู่ขอบเขตการปกครอง แบ่งประมวลผลเป็นรายจังหวัด
   เพื่อไม่ให้เกินขีดจำกัดของ Earth Engine
4. **คำนวณดัชนีเสี่ยง** — คูณ Hazard กับพื้นที่ปลูกรายพืช (Exposure) และความเปราะบางของพื้นที่
   (Vulnerability) พร้อมตัวคูณความอ่อนไหวรายพืชและระยะการเจริญเติบโต
5. **บันทึกผล** — เขียนลง `drought_risk` พร้อม `model_version` และคอลัมน์ `src`
   ที่ระบุชุดข้อมูลต้นทางของทุกแถว ค่าที่ขาดหาย (เมฆบัง ไม่มีซีน) คงไว้เป็น NULL ไม่เติมค่าแทน
6. **ให้บริการข้อมูล** — FastAPI อ่านรอบล่าสุด ส่งเป็น GeoJSON หรือ Vector Tile ให้ MapLibre วาดบนแผนที่

## 4. เทคโนโลยีที่ใช้และเหตุผล

| ชั้น | เทคโนโลยี | เหตุผลที่เลือก |
|---|---|---|
| Frontend | MapLibre GL JS 4.7 | เรนเดอร์ด้วย WebGL รองรับโพลิกอนจำนวนมากบนมือถือ เป็นโอเพนซอร์สเต็มรูปแบบ ไม่มีค่าสิทธิ์การใช้งาน |
| Backend | FastAPI + Uvicorn | สร้างเอกสาร OpenAPI อัตโนมัติ รองรับ async และเขียนด้วย Python จึงเชื่อมกับ pipeline ได้โดยตรง |
| Database | PostgreSQL 16 + PostGIS 3.4 | รองรับ ST_Intersects, ST_AsMVT และส่งออกไฟล์ GIS ผ่าน ogr2ogr ได้โดยตรง |

## 5. สูตรดัชนี

ยึดกรอบ `Risk = Hazard × Exposure × Vulnerability` ตามแนวทางสากลด้านการประเมินความเสี่ยงภัยพิบัติ

| องค์ประกอบ | ตัวแปร | ที่มาของแนวคิด |
|---|---|---|
| Hazard | 0.40·SPI-3 + 0.30·ความชื้นดิน + 0.30·VHI | แนวคิด Combined Drought Indicator ที่เชื่อมสามสัญญาณ คือฝนขาด ความชื้นดินลด และพืชเครียด |
| Exposure | พื้นที่ปลูกรายพืช (ไร่) | ทะเบียนเกษตรกรและชั้นข้อมูลพื้นที่ปลูก |
| Vulnerability | สัดส่วนพื้นที่นอกเขตชลประทาน + ความสามารถอุ้มน้ำของกลุ่มชุดดิน | กรมชลประทาน และกรมพัฒนาที่ดิน |

**ตัวคูณความอ่อนไหวรายพืช:** ข้าว 1.00 · ข้าวโพด 0.88 · อ้อย 0.78 · มันสำปะหลัง 0.62
**ตัวคูณระยะการเจริญเติบโต:** ข้าวช่วงตั้งท้อง 1.3 · ข้าวโพดช่วงออกไหม 1.4 · มันสำปะหลังช่วงตั้งตัว 1.3

ชั้นความเสี่ยงแบ่ง 5 ระดับที่ค่า 0.20 / 0.40 / 0.60 / 0.80 ใช้ชุดสี YlOrRd
ซึ่งเรียงลำดับถูกต้องตามการรับรู้ของสายตาและปลอดภัยสำหรับผู้ที่มีภาวะตาบอดสี
โดยหลีกเลี่ยงคู่สีเขียว–แดง

## 6. แผนการตรวจสอบความถูกต้อง

| ชั้น | เทียบกับข้อมูลใด | ตัวชี้วัด |
|---|---|---|
| 1 ฟิสิกส์ | ความชื้นดินจากสถานีวัดภาคสนาม และผลิตภัณฑ์ SMAP | r, RMSE, ubRMSE |
| 2 ดัชนี | SPI/SPEI และ VHI จากแหล่งมาตรฐาน | สหสัมพันธ์ และ lag correlation |
| 3 เหตุการณ์ | ประกาศเขตพื้นที่ประสบภัยแล้งรายอำเภอ | POD, FAR, CSI, Cohen's Kappa |
| 4 ผลกระทบ | ผลผลิตต่อไร่รายจังหวัด และพื้นที่เกษตรเสียหาย | R², MAE ของ yield anomaly |

**การแบ่งข้อมูล** ต้องใช้ spatial block cross-validation แบ่งตามภาคหรือลุ่มน้ำ
ห้ามสุ่มแยกรายพิกเซล เพราะ spatial autocorrelation ทำให้ค่าความแม่นยำสูงเกินจริง
และต้องกันปีที่เกิดเอลนีโญรุนแรงไว้เป็นชุดทดสอบ

**ข้อควรระวัง** ประกาศเขตภัยพิบัติสะท้อนกระบวนการบริหาร ทั้งการร้องขอจากพื้นที่ งบประมาณเยียวยา
และดุลยพินิจของผู้บริหาร จึงไม่ใช่ความจริงทางกายภาพล้วน ๆ ต้องใช้ควบคู่กับข้อมูลผลผลิตเสมอ

## 7. สถานะปัจจุบันและแผนพัฒนาต่อ

| ลำดับ | งาน | สถานะ |
|---|---|---|
| 1 | โครงสร้าง Frontend–Backend–Database–API ครบวงจร | เสร็จแล้ว ผ่านการทดสอบอัตโนมัติ 15 รายการ |
| 2 | ขอบเขตการปกครอง 928 อำเภอ | เสร็จแล้ว ใช้ข้อมูลจริง |
| 3 | เชื่อมต่อ Google Earth Engine เพื่อคำนวณดัชนีจริง | อยู่ระหว่างดำเนินการ |
| 4 | ตรวจสอบความถูกต้องตามแผน 4 ชั้น | รอข้อ 3 |
| 5 | นำเข้าขอบเขตแปลงเกษตรจริงและจำแนกชนิดพืช | วางแนวทางไว้ใน `docs/REAL_DATA_RECIPES.md` |

| 7 | โมเดลพยากรณ์เชิงพื้นที่และเวลา 30–90 วัน | แผนระยะถัดไป |
